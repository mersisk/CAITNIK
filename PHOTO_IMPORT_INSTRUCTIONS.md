# Инструкция Codex: массовая расстановка фотографий по каталогу «Арт‑Деко»

## Главная задача
Используй фотографии из папки `assets/` как источник истины для каталога сайта. Структура папок соответствует структуре каталога: категория → услуга → при наличии ценовой вариант → фотографии.

Перед изменениями изучи текущую реализацию каталога и найди, где хранятся названия разделов, варианты, цены и массивы изображений. Не переписывай сайт целиком и не меняй дизайн без необходимости.

## Правило сопоставления
1. Верхняя папка = раздел/категория каталога.
2. Вложенная папка = услуга/подраздел.
3. Если внутри услуги есть подпапки с ценой (`от 2500`, `от 5000`, `от 7000`, `от 25 000`, `от 35 000`, `от 45 000`) — каждая такая папка соответствует отдельному ценовому варианту на сайте.
4. Все изображения внутри ценовой папки должны попасть только в галерею этого ценового варианта.
5. Если внутри услуги НЕТ подпапок с ценой — это услуга с индивидуальным расчётом. Не придумывай цену. На сайте для неё должно остаться/появиться состояние «Расчёт индивидуальный» и кнопка «Заказать оформление» (используй существующий стиль сайта).
6. Если категория сама содержит фотографии без подпапок, используй их для соответствующей общей карточки/галереи этой категории. Не создавай искусственных ценовых вариантов.
7. Названия карточек/разделов на сайте приводи к смыслу названий папок. Очевидные опечатки в именах папок (`Офрмление`, `Свальба`) НЕ переносить в интерфейс — использовать грамотные формы «Оформление свадебного зала», «Свадьба под ключ».
8. Не смешивай фотографии между соседними папками и ценовыми вариантами.

## Очень важные требования к изображениям
1. Не обрезай значимые части фотографий.
2. Не растягивай изображения и не меняй их пропорции.
3. Сохраняй исходное соотношение сторон каждой фотографии.
4. Для основной фотографии/слайдера используй отображение без кропа: `object-fit: contain` и корректное центрирование.
5. Контейнер галереи должен адаптироваться к горизонтальным и вертикальным фотографиям. Если текущий фиксированный контейнер режет вертикальные фото — исправь CSS так, чтобы вся фотография была видна.
6. Не увеличивай маленькое изображение агрессивно выше его естественного качества. Избегай пикселизации.
7. Не преобразовывай и не генерируй новые картинки. Используй только исходные файлы из `assets/`.
8. Не применяй автоматический AI-crop, face-crop или изменение композиции.
9. Для миниатюр допустим аккуратный `cover` только если это не влияет на просмотр оригинала: при открытии/переключении полный кадр обязан отображаться без обрезки.
10. Сохраняй существующие стрелки, индикаторы, свайпы и адаптивность галереи.

## Порядок фото
Сохраняй естественный числовой порядок по имени (`photo_1`, `photo_2`, ... `photo_10`, ...), а не лексикографический порядок, где `photo_10` может оказаться перед `photo_2`.
Если в одной папке встречаются несколько файлов с одинаковым номером, не удаляй их: используй все, сортируя стабильно по номеру и затем по полному имени файла.

## Цены
Нормализуй отображение цен:
- `от 2500 к` → `от 2 500 ₽`
- `от 5000 к` → `от 5 000 ₽`
- `от 7000 к` → `от 7 000 ₽`
- `от 25 000` / `от 25 000к` → `от 25 000 ₽`
- `от 35 000` → `от 35 000 ₽`
- `от 45 000` → `от 45 000 ₽`

Не трактуй букву «к» в названиях этих папок как дополнительное умножение на 1000: папка `от 2500 к` означает 2 500 ₽, а `от 25 000к` — 25 000 ₽.

## Безопасность изменений
- Не трогай backend, базу данных, Telegram, форму заявки, юридические страницы и серверные настройки в рамках этой задачи.
- Не меняй тексты и цены в других карточках, если этого не требует структура папок.
- Не удаляй фотографии из `assets/`.
- Не вставляй base64-изображения в JS/HTML.
- Используй нормальные относительные пути к локальным файлам.

## Рабочий процесс
Сначала:
1. Проанализируй `assets/` и текущий каталог сайта.
2. Составь краткую таблицу `папка → раздел сайта → вариант/цена → количество фото`.
3. Отдельно перечисли только реальные неоднозначности, если они есть.
4. Если сопоставление очевидно, после таблицы можешь сразу выполнить массовую замену; не спрашивай подтверждение для каждой фотографии.
5. После изменений запусти существующие проверки/сборку проекта.
6. Покажи список изменённых файлов и кратко сообщи, какие разделы обновлены.
7. Не делай push/commit без отдельной команды пользователя, если это не было явно запрошено в текущем диалоге.
